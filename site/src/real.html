The graduation · Drill 6

Do it for real 🚀

Every level in the Quest was practice in a safe sandbox. This is the same loop — branch, commit, push, PR, resolve a conflict — now on a real GitHub repo, by hand. Nothing simulated. You finish with a live Pull Request that has your name on it, and a real merge conflict you resolved yourself.

💡 The one idea: the same six moves from the Quest, now with real stakes. At Wix, tooling like Creator Kit (/ck-new, /ck-utility-pr, /ck-utility-sync) runs these exact git steps for you. You're about to do them by hand — so you'll recognise what that tooling does, instead of trusting it blindly.
🔧 Prerequisites (~5 min): git installed, a GitHub account, and the workshop repo cloned with collaborator access — send the facilitator your GitHub username, or use the Fork fallback. gh (GitHub CLI) is handy but optional; you can always open the PR in the browser.

The loop

  1. Get current — clean slate

    In your clone: git checkout main then git pull. main is one shared line of work — start clean, every time. The single most-skipped step.

    ↳ Level 1 · a branch is not a folder

  2. Start your piece — one branch, one thing

    Name a branch for you + one small topic: git switch -c dana-first-pr (git checkout -b works too). Make your own folder workshop/dana-first-pr/ so 20 people work at once without colliding.

    ↳ Level 4 · one branch, one thing

  3. Build something real — commit as you go

    Need a topic? Pick a Wix AI feature → and write a quick one-pager in your folder. Then git add <file> and git commit -m "…". git add curates exactly what goes in; git status tells the truth any time.

    ↳ Level 2 · staging

  4. Draft PR early — back it up now

    Don't wait until you're "done": git push -u origin dana-first-pr, then gh pr create --draft (or open the link git push prints). The moment it exists, your work lives on GitHub — not just your laptop.

    ↳ Level 4 · the way out

  5. Keep going — push to the same PR

    Change something, then git commit + git push. Reload the PR: the new commit is already there. No second PR, no lost work — the PR updates itself.

  6. The conversation — a PR is a comment thread

    Pair up. Comment on a neighbour's PR line. When one lands on yours, answer it with another commit (git commit → git push). The ask, your fix, and the resolution stay on the change forever.

    ↳ Level 5 · a PR is a conversation

🔥 The conflict finale

The scariest level was the pull conflict — and here it's real, on the live repo. By the end you'll have hit a genuine merge conflict and resolved it yourself.

1. Sign the shared line. On your branch, open conflict-zone/guestbook.md and change the single line - 🕶️ The instructor was here first. to your own name. Then git add → git commit → git push to your PR.

2. Wait for the go-ahead. Your facilitator changes that same line on main. Now main and your branch disagree on the exact same line — the conflict, set up on purpose.

3. Pull it in and resolve. Run git pull origin main — that pulls main's new line into your branch (not plain git merge main — your local main is stale). Git stops with CONFLICT … guestbook.md. Open the file, delete the <<<<<<< / ======= / >>>>>>> markers, keep the text you want (keeping both is easiest), then git add → git commit → git push. That's the whole monster.
🧯 Escape hatch: git merge --abort puts everything back exactly as before — nothing lost.  ·  🧑‍💻 On your own? Play both roles: branch roster-a, edit the line, merge it to main; then on roster-b edit the same line and git pull origin main — identical conflict, only you.

What just happened

  • The daily loop is exactly the Quest loop: get current → branch → build → draft PR → push more → resolve → merge. Same six moves, real stakes.
  • You ran every git step by hand — so when Wix tooling like Creator Kit does it for you, you'll recognise the gears instead of fearing them.
  • A draft PR from commit one means your work is backed up and shareable the whole time — never trapped on one laptop.
  • A PR is a conversation bolted to the actual change. You're already fluent in that.
🧹 When it's merged: click GitHub's "Delete branch", then git checkout main && git pull for whatever's next.
